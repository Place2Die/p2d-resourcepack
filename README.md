# p2d-resourcepack

The Place2Die server resource pack: one pack, required on join, carrying the models and
textures of every custom item (and, through BetterModel, every custom mob).

Targets **Minecraft Java 26.2** (Paper 26.2): resource pack format **88**
(`min_format`/`max_format` in `pack/pack.mcmeta`, the format scheme since 1.21.9).

## Layout

```
pack/                         the pack sources, zipped as-is
  pack.mcmeta
  assets/
    p2d_survival/             one namespace per plugin = the plugin's key namespace
      items/<id>.json         item definition, read by the item_model component
      models/item/<id>.json   the model
      textures/item/<id>.png  the texture
    p2d_gathering/            items (materials, tools) and harvest node models
      textures/block/<id>.png node textures (cube models shown by an item display)
    p2d_zombies/ p2d_loot/ …  (added with their first asset)
bettermodel/ or bettermodel.zip   optional, BetterModel's generated pack (see below)
tools/p2dpack/                build tooling (Python 3.13, standard library only)
tests/                        unittest suite of the tooling
scripts/placeholders.py       generates the placeholder textures
pack.py                       entry point
```

## Commands

```sh
./pack.py validate          # check the sources
./pack.py build             # validate, merge BetterModel's pack, zip, print the SHA-1
./pack.py version           # next release tag computed from the gitmojis since the last tag
python3 -m unittest discover -s tests -t .
```

`build` writes `build/p2d-resourcepack.zip` and `build/p2d-resourcepack.zip.sha1`. The zip
is deterministic (sorted entries, fixed timestamps and permissions), so the same sources
always give the same SHA-1.

### What `validate` checks

- `pack.mcmeta` parses and its `min_format`..`max_format` range includes 88.
- Every `.json` / `.mcmeta` parses, with no duplicate keys.
- Namespaces use `[a-z0-9_.-]` and asset paths `[a-z0-9_./-]` (lowercase): Minecraft
  silently ignores anything else. Only `pack.mcmeta`, `pack.png` and `assets/` at the root.
- Every `.png` is a real PNG.
- Every item definition (`assets/<ns>/items/*.json`) points to models that exist, at any
  depth (`select` cases, `condition`, `range_dispatch`, `composite`, `special` bases).
- Every model's parent and textures exist. A texture outside `item/` or `block/` is a
  warning: it is only stitched into the atlas if the pack adds an atlas source for it.

References into the `minecraft` namespace (`item/generated`, vanilla textures) are vanilla
assets, so they are trusted, not checked.

## Adding an item model

Every custom item has its own model and texture (rule decided on 2026-10-15). For an item
`p2d_<plugin>:<id>`:

1. **Texture**: `pack/assets/p2d_<plugin>/textures/item/<id>.png`, 16x16 (or a larger
   power of two). Lowercase file names.
2. **Model**: `pack/assets/p2d_<plugin>/models/item/<id>.json`
   ```json
   {
     "parent": "minecraft:item/generated",
     "textures": { "layer0": "p2d_<plugin>:item/<id>" }
   }
   ```
   (`minecraft:item/handheld` for tools and weapons; a Blockbench export for 3D items.)
3. **Item definition**: `pack/assets/p2d_<plugin>/items/<id>.json`
   ```json
   { "model": { "type": "minecraft:model", "model": "p2d_<plugin>:item/<id>" } }
   ```
4. `./pack.py build` and `python3 -m unittest discover -s tests -t .` must pass.
5. Commit with `:bento:` (assets, patch release) or `:sparkles:`, ending with the ticket id,
   and open a PR. Once it is merged and released, the plugin can set the model:
   `CustomItem.Builder#model(ItemModel.model(Key.key("p2d_<plugin>", "<id>")))`.
   Never set `item_model` before the released pack ships the asset: the item renders as the
   missing texture.

### World objects shown by an item display

Core custom blocks can be rendered by an item display whose `item_model` is the block's key
(harvest nodes do: an invisible barrier hitbox under the model). They follow the same three
steps; a block-shaped placeholder uses `"parent": "minecraft:block/cube_all"` with
`"textures": { "all": "p2d_<plugin>:block/<id>" }` and its texture under `textures/block/`.

Tree nodes come in sizes (PERSO-113): `tree_small`, `tree` (medium) and `tree_large`, each with a
`_depleted` model. Their placeholders are boxes of different sizes (`elements` with
`parent: minecraft:block/block`) so the sizes read apart in game before the real models exist.

## BetterModel (3D mobs)

BetterModel (PERSO-84) renders the Blockbench mob models and generates its own pack. Players
must get one pack, so `build` merges it into ours:

- Input: `./bettermodel/` (BetterModel's `pack-type: folder` output) or `./bettermodel.zip`
  (`pack-type: zip`), or any path with `./pack.py build --bettermodel <path>`. Absent =
  nothing merged.
- Only its `assets/` are merged. Its `pack.mcmeta` and `pack.png` are replaced by ours.
- A file both packs ship with different content is a **conflict and fails the build**; a
  byte-identical file is kept once.
- Anything else at its root (overlay folders) fails the build: set BetterModel's
  `pack.generate-legacy-model: false`, we only target 26.2.
- The merged pack is validated again before zipping.

## Releases

CI (`.github/workflows/build.yml`) runs the tests and the build on every PR and push, checks
the zip is reproducible, and uploads it as an artifact. On `main`, the version is computed
from the gitmojis since the last `vX.Y.Z` tag (`:boom:` major, `:sparkles:` minor, patch
gitmojis such as `:bento:` and `:bug:` patch, others no release) and a GitHub release
`vX.Y.Z` is published with the zip and its SHA-1. Nobody tags by hand.

The repository is private, so release assets are not downloadable by Minecraft clients: the
pack must be served from a public URL (see the open question in PERSO-81).
